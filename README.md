# rmate на Go

Клиент протокола rmate для редактирования удалённых файлов в TextMate 2 и
других редакторах с сервером rmate. Реализован по поведению
[rmate-python](https://github.com/sclukey/rmate-python), использует только
стандартную библиотеку Go и собирается в один исполняемый файл.

## Сборка

Требуется Go 1.22 или новее. Основные платформы — Linux и macOS.

```sh
go build -o rmate .
./rmate --help
```

Перенесите бинарник в каталог из `PATH` на удалённой машине.
Для сборки под другую архитектуру, например Linux amd64:

```sh
GOOS=linux GOARCH=amd64 go build -o /tmp/rmate-linux-amd64 .
```

На платформах без Unix доступен режим `--wait`; фоновый режим требует Unix.

## Подключение

Включите приём rmate-подключений в настройках локального редактора.
Создайте обратный SSH-туннель с локальной машины:

```sh
ssh -R 52698:localhost:52698 user@server
```

В SSH-сессии запустите:

```sh
rmate main.go
rmate --wait -l 42 main.go
rmate -m 'Main' -m 'Config' -t go -t json main.go config.json
```

Клиент передаёт содержимое файлов редактору и записывает полученные сохранения
на удалённой машине. Можно открывать ещё не существующие файлы; они появятся
при первом сохранении, если родительский каталог существует.

По умолчанию команда возвращает управление после подключения и отправки
файлов. Отдельный процесс продолжает принимать сохранения до закрытия
документов или соединения. С `--wait` команда ждёт закрытия всех документов.
Ошибки подключения возвращают ненулевой код и в фоновом режиме.

## Стандартный ввод и вывод

`-` открывает stdin. Если имена файлов не указаны, клиент читает stdin из
конвейера, а при запуске в терминале завершает работу без подключения.

```sh
printf 'hello\n' | rmate --wait -
printf 'hello\n' | rmate --wait - > edited.txt
```

Когда stdout перенаправлен, после закрытия документа stdin клиент выводит
последнюю сохранённую версию, либо исходный текст, если сохранений не было.
Байты передаются без преобразования кодировки и без добавления перевода строки.
Для конвейеров и скриптов рекомендуется `--wait`.

## Опции

| Опция | Назначение |
| --- | --- |
| `--host HOST` | Адрес редактора; по умолчанию `localhost` |
| `-p`, `--port PORT` | TCP-порт; по умолчанию `52698` |
| `-w`, `--wait` | Ждать закрытия документов |
| `--no-wait` | Принимать сохранения в фоновом процессе; режим по умолчанию |
| `-l`, `--line LINE` | Строка или строка выделения TextMate, например `12:3` |
| `-m`, `--name NAME` | Имя документа в редакторе |
| `-t`, `--type TYPE` | Тип файла в редакторе |
| `-f`, `--force` | Открыть файл, недоступный для записи |
| `-v`, `--verbose` | Диагностика в stderr |
| `-h`, `--help` | Справка |
| `--version` | Версия |

Повторяющиеся `--line`, `--name`, `--type` применяются к файлам по порядку.
Поддерживаются `--port=52698`, `-l42`, объединение коротких флагов (`-wv`),
опции после имён файлов и `--` для имён, начинающихся с дефиса.

`--force` разрешает открытие, но не меняет права доступа. Ошибка записи
сообщается в stderr; с `--wait` также возвращается ненулевой код завершения.

## Конфигурация

Файлы читаются последовательно: `/etc/rmate.rc`, `/usr/local/etc/rmate.rc`,
`~/.rmate.rc`. Последующий файл переопределяет предыдущий. Формат без секций:

```ini
host = localhost
port = 52698
```

Также поддерживается разделитель `:` и строки комментариев с `#` или `;`.
Переменные `RMATE_HOST` и `RMATE_PORT` переопределяют файлы конфигурации,
а аргументы командной строки переопределяют переменные окружения.

Значение `host = auto` использует адрес SSH-клиента из `SSH_CONNECTION`;
при отсутствии этой переменной используется `localhost`.

## Сохранение и совместимость

Файлы записываются на месте: сохраняются права доступа, владелец и связи через
символические и жёсткие ссылки. До записи создаётся резервная копия `file~`
с правами `0600`; если такое имя занято, добавляются дополнительные `~`.
После успешной записи и синхронизации новая резервная копия удаляется.
При ошибке записи она остаётся, а её путь выводится в stderr.

Поддерживаются сообщения `open`, `save`, `close`, несколько документов в одном
соединении и несколько блоков `data` в ответе. Заголовки ограничены 64 КиБ
на строку; размер содержимого этим ограничением не ограничивается.
Содержимое документов находится в памяти.

В отличие от Python-клиента, вывод stdin сохраняется побайтно и появляется
только при закрытии соответствующего документа. Ошибки чтения файлов и записи
сообщаются явно. Каталоги, специальные файлы, повторное открытие stdin,
повторяющиеся токены документов и переводы строк в метаданных отклоняются.

Совместимость проверена тестовым TCP-сервером, воспроизводящим протокол.
Ручная проверка с настоящим TextMate не выполнялась.

## Проверка

```sh
go test -race ./...
go vet ./...
```

Тесты проверяют протокол, двоичные данные, пустые сохранения, конфигурацию,
права и ссылки, stdin/stdout, запуск настоящего бинарника в обоих режимах и
синхронное сообщение об ошибке подключения.
